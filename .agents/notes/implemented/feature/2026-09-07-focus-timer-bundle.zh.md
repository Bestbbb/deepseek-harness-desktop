# Agent Note: 可选专注计时器组合包

Status: implemented

[English](2026-09-07-focus-timer-bundle.md) | 中文

## 问题

插件市场需要一个可用且无需账号的包，证明 UI 扩展也是可安装组合包，而不只是 Skill 文件或测试贡献。小型便利功能不应引入后台 Host 工作或改变智能体执行。

## 决策

[专注计时器](../../../../packages/desktop/focus-timer/README.zh.md)是可选组合包，挂载自己的侧栏操作。Host 入口在现有设置提供方中注册可选的时长偏好。组件本地的系统时钟截止时间仅在计时运行时驱动秒级渲染；关闭对话框保留倒计时状态，卸载或刷新页面清除状态。用户选择不超过一天的整数时长。计时器不依赖模型或通知。

桌面准备流程使用固定版本的包管理器、禁用脚本来打包仓库自有代码，发布内容寻址的 tarball，再原子发布其目录记录。记录固定文件内容、包版本、Harness 版本及构建目标。该包不属于默认运行时依赖，使上游 Bundle 解析器选择 Profile 中安装的产物。开发模式将相同源码准备到独立的生成资源目录。测试使用私有目录，不将测试包填入产品目录。

审核过的 tarball 通过 `bundledDependencies` 携带 schema 库及其传递依赖。仅打包命令选择 pnpm 的 hoisted 打包模式；工作区保留隔离安装布局。未随包携带的生产依赖需要安装器空离线缓存中不存在的注册表元数据，因而阻止启用。打包验收使用真实的固定版本 pnpm 及空的私有缓存，检测不完整的依赖内容。

可选市场入口使用现有键控 Slots 机制，以组合包的 npm 名称为键。入口与侧栏仅通过注册项声明的存储共享可见状态；侧栏独自拥有倒计时及刷新间隔。先关闭设置再打开计时器，避免模态框所有者相互竞争。入口跟随市场和侧栏的声明，因此任一所有者卸载都不会留下无法使用的操作。不需要功能间的运行时导入或独立操作注册表。

插件配置属于插件自己的计时器面板。显式保存和清除使用现有 Host 设置作用域，并携带面板所显示的修订号。已保存时长标签跟随 Host 观测值；写入被拒绝或无法确认时保留草稿，不声称成功。新计时器采用已保存偏好但不自动开始；其他设置写入者修改偏好时，运行中或暂停的计时器保留已选择的时长。倒计时进度不进入设置文档或会话日志。

## 考虑过的替代方案

**将计时器放进侧栏所有者。** 不采用，因为用户必须能够通过正常组合包组合增删此能力，而不需要分叉外壳实现。

**持久化计时器或将计时移到 Host 服务。** 对此本地倒计时不采用，因为这会引入提醒持久性及通知义务。界面明确说明生命周期及不提供闹钟。

**在市场或浏览器本地存储中保存偏好。** 不采用，因为插件已经拥有自己的设置命名空间，现有 Host 作用域提供校验、修订号检查和跨浏览器刷新持久化，无需第二个设置所有者。

**将无实际功能的测试包作为首个目录条目。** 不采用，因为准备成功本身不提供用户操作，也不能证明已安装浏览器贡献有实际用途。

## 后果

此组合包提供侧栏和市场使用入口，不增加模型循环的工作。它不是能跨睡眠、节流或退出应用可靠运行的闹钟。单元测试覆盖计时、设置校验、保存失败、共享可见状态及声明清理；双语浏览器预期覆盖保存、刷新和清除；打包验收通过市场确认安装真实产物，启动候选 Profile，从“已安装”打开并重新打开同一个计时器，重启 Host 后验证已保存时长，再通过市场确认移除组合包。该验收仅模拟原生选择；真实原生启用及恢复仍由独立 Rust 所有者负责。图形安装与卸载属于市场，而非此组合包。
