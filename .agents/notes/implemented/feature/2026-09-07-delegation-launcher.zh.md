# Agent Note: 将人工委派作为可选组合包

Status: implemented

[English](2026-09-07-delegation-launcher.md) | 中文

## 问题

提供方配置不能证明任务已调用或成功执行。非开发者需要明确的任务入口，而不是第二套 agent（智能体）调度器或隐式账户访问。

## 决策

[委派组合包](../../../../packages/desktop/delegation-launcher/README.zh.md)在现有 subagent 和按所属方限定的 Jobs 服务之上注册人工命令。命令负责 JSON 及任务字节验证；Jobs 负责受理、取消和清理。组合包限制面板读取量，并配置任务控制器的完成通知上限。命令输入与结果使用已有会话事件类型。编辑器只列出已加载提供方，并要求在提交前逐任务确认。

浏览器直接使用现有 Commands Remote 结果。SessionFace.command 有意只返回匹配标志，而空白会话在模型轮次开始前隐藏会话内容。在插件内显示命令真实结果，可避免误导性的确认，无需改变上游空白会话语义。连接变更使确认失效；未确认的写入绝不重放。

面板从 Session 控制流接收实时任务状态，通过自己的 Remote 提供显式终态读取及经确认的取消。执行方要求任务严格属于当前会话且为 subagent 类型。关闭面板丢弃输出但不取消工作；取消回执与提供方清理分开。此设计让空白会话也能完成委派操作，无需第二套任务注册表。

[本地 agent 启用决策](2026-09-06-desktop-local-agent-opt-ins.zh.md)仍独立负责提供方配置、原生诊断和模型工具授权。此组合包通过已加载提供方调用人工授权的任务，不修改这些偏好。桌面审核目录分发其确切产物；仅安装不会配置提供方或启动工作。其已安装使用入口先关闭“设置”，再打开共享委派面板。

## 考虑过的替代方案

**从编辑器直接启动产品 CLI（命令行界面）。** 否决，因为它重复实现提供方认证、进程归属和结果规范化。

**将传输响应成功视为任务成功。** 否决，因为命令受理可能失败，执行是异步的，成功入队后也可能丢失响应。

**为此插件改变上游空白会话规则。** 否决，因为插件可以通过现有服务显示命令结果和任务控件，无需更改会话渲染。

## 影响

编辑器不增加轮询或启动时 agent 探测。待处理任务在插件移除后仍存在，直到提供方清理完成都由 Jobs 负责。提供方基础设施诊断转为通用任务错误；返回的任务文本不会被视为可信指令。授权前明确告知提供方上下文继承及可能的父级模型唤醒。

针对性测试覆盖命令日志、重复点击、陈旧读取、会话归属、UTF-8 限制、取消、延迟清理、提供方移除和可撤销 UI 注册。提供方名称按序显示，不改变注册顺序。打包运行时的浏览器冒烟测试离线安装审核产物，打开已安装入口，读取及取消真实任务，并在不改变源组合或设置的情况下移除组合包。测试控制外部提供方和原生排队响应，并为隔离的 PATH 明确组合真实的应用内目录选择器。原生候选选择及启动失败恢复有独立 Rust 证据。真实账户推理、模型可见父级完成回放及完整原生窗口验收仍有缺口；不声明公开市场已完成。
