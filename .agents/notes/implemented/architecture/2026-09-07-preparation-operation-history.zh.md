# Agent Note: 准备历史是观测记录，不是启用授权

Status: implemented

[English](2026-09-07-preparation-operation-history.md) | 中文

## 问题

重启后的服务不能仅凭目录存在就区分成功准备与遗留目录。另一个仍在运行的进程可能拥有未完成任务，而回执缺失或变化会使先前记录的结果失效。基于时间戳自动清理可能删除其他进程的候选。

## 决策

可选的[准备日志](../../../../packages/desktop/bundle-preparation/README.zh.md#operation-history) 将每个获准操作记录在独占创建的操作目录中。开始元数据先于任务写入；终态元数据在任务及清理完成后写入。独立标识避免跨进程读改写所有权。元数据复用现有原子写入库；发布不执行 fsync，也不承诺断电后保留。

读取方只把自身的当前操作标为 `preparing`。其他未结束记录保留为 `unsettled`，不宣称其所属进程已停止。损坏元数据仍以 `unreadable` 显示。已准备观测校验有界回执的哈希，不校验可执行内容或运行时健康；回执变化或缺失则为 `unavailable`。历史不授予启用权限，也不触发重试或删除。

部署方管理有读取限制的历史目录，并将其与暂存目录及配置的源 Profile 分开。未知条目或过量历史使读取显式失败。失败元数据不包含原始错误、子进程输出或配置。终态写入失败会拒绝请求，并可能留下已完成的候选文件；再次记录失败则留下未结束操作。调用方负责保留期限及后续调查。

## 考虑过的替代方案

**根据时间或目录存在推断任务已放弃。** 拒绝，因为其他仍在运行的进程可能仍拥有该操作。恢复需要显式所有权及准入判断，不能依赖超时猜测。

**将成功回执视为启用授权。** 拒绝，因为可执行内容可能独立变化，且尚未进行生效运行时健康检查。

**维护共享可变 JSON 索引。** 拒绝，因为独立操作不需要共享读改写协调；独占操作目录与原子记录可保持这种分离。

## 影响

服务重建可保留观测，不改变 Profile 或 Session。定向测试覆盖当前操作归属、记录限制、无效数据、回执变化、发布失败及独占标识。打包冒烟测试在新 dsh 进程中读取成功的组合操作和失败的依赖操作，不启用候选。

这是只读重启历史，不是自动崩溃恢复或安装回滚。[文件准备](2026-09-06-reviewed-bundle-preparation.zh.md)、[依赖候选](2026-09-06-offline-bundle-candidates.zh.md)和 [Profile 组合](2026-09-07-candidate-profile-composition.zh.md)决策仍保留各自独立的验证与隔离理由。任务空闲准入、生产切换及市场 UI 仍由[插件市场提案](../../proposed/architecture/2026-09-06-desktop-plugin-marketplace.zh.md)管理。
