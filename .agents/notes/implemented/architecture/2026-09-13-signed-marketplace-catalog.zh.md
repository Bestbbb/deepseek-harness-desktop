# Agent Note: 签名插件市场目录选择

Status: implemented

[English](2026-09-13-signed-marketplace-catalog.md) | 中文

## 问题

独立于应用发行版分发的目录可能在用户审核与安装之间变化。未经认证的目录提供产物哈希，并不能确立审核授权；有效的旧签名也可能重新引入已撤回的代码。

## 决策

[准备服务](../../../../packages/desktop/bundle-preparation/README.zh.md)接受可选的部署方固定 HTTPS 频道与 Ed25519 公钥。内部远程目录读取器认证准确载荷字节，验证完整元数据，并限制源、大小、有效期和频道。现有 Cordis 服务负责选择与取消；[浏览器网关](2026-09-07-desktop-marketplace-browser.zh.md)提供显式刷新与确认。不修改 agent loop（智能体循环），不新增原生加载器、发布者登录或任意安装 URL。

信封包含 schemaVersion 1、规范 base64 编码的 payload 和 signature 字段。签名 JSON 载荷包含 schemaVersion 1、channel、正整数 revision、issuedAt、expiresAt、artifactBaseUrl 及现有 catalog 文档。空目录可撤回全部可发现条目。每个在线条目必须具备双语审核指导。HTTPS 产物文件名仅来自已验证记录；下载拒绝重定向且不携带继承凭据，暂存检查准确大小及 SHA-256 后才进入现有离线准备流程。

启动仅读取缓存。缓存不存在时允许内置发现；已知过期或损坏的缓存不允许回退。刷新先认证响应，再在现有 atomic-write 锁内重读缓存，拒绝回退及同一版本内容冲突后替换。刷新与准备互斥。安装确认携带签名版本和完整条目的摘要，在准备前及向原生队列发送前立即核对。过期或审核元数据变化要求重新审核；原生 Profile 与版本检查仍独立执行。

[本地准备决策](2026-09-06-reviewed-bundle-preparation.zh.md)保留暂存归属和回执语义，不负责在线信任。更广泛的[市场提案](../../proposed/architecture/2026-09-06-desktop-plugin-marketplace.zh.md)仍负责发布运营、插件就绪及产品验收；两份早期记录均未被完全取代。

## 考虑过的替代方案

**只信任 HTTPS 和相邻校验值。** 拒绝，因为托管服务被攻破时元数据和校验值都可能被替换。部署固定签名认证独立的目录授权者。

**在线元数据失败就回退到内置目录。** 拒绝，因为过期或已撤回的在线条目可能静默重新变为可安装。只有从未缓存的部署从内置元数据开始。

**立即添加独立目录服务和账户后端。** 拒绝，因为准备服务已负责选择，所有消费方共享其生命周期。GitHub 审核与静态签名元数据不需要用户账号；提供方独立演化时才有理由进一步拆分。

## 后果

签名读取器、有界传输、缓存竞态、有效期、篡改、陈旧确认及 Cordis dispose（资源释放）均有专项测试。浏览器验收 fixture（测试前置数据）通过真实 Loader 和已认证网关展示显式在线检查控件；服务测试用替代 HTTPS 响应验证签名传输。这不等于公开托管或原生 WebView 验收。

公开目录部署、发布者审核自动化、签名密钥管理及应用分发仍未完成；打包桌面默认不配置远程频道。密钥轮换只接受可信部署配置分发的公钥，不支持远程提供的信任根更新。私钥必须置于目录和应用包之外。缓存写入原子但不保证断电持久性，本地删除、文件系统回退或时钟篡改会破坏缓存版本下限。遗留写入锁需要操作人员恢复。目录撤回不会禁用或删除已安装代码，Host 插件仍拥有 Harness 访问能力；这不是 TUF，也不是插件隔离。
