# Agent Note: 原生宿主的下次启动 Profile 选择

Status: implemented

[English](2026-09-07-desktop-profile-startup-selection.md) | 中文

## 问题

准备好的 Bundle 组合需要由插件运行时之外的组件管理可恢复的启动选择。切换 Harness 主目录会隐藏已有会话和凭据。在偶发的运行时重试中启用候选组合，也可能在桌面任务尚未结束时改变插件。

## 决策

[原生选择所有者](../../../../apps/desktop/src-tauri/src/profiles.rs)在桌面 Harness 主目录中保存一份带版本的选择记录。经过认证的桥接接口提供选择查询、候选排队和精确取消待启用项。排队要求候选使用生成的 `desktop-<UUIDv4>` Profile 名称，清单 SHA-256 匹配，当前活动前任未改变，并且只在启动时重新加载补丁。这些检查确定选择身份，不代表代码已经审核或软件包完整性验证；软件包策略仍由 Harness 准备服务负责。

只有所有者的首次应用启动会消费待启用候选。它先持久化试启动记录，再用原主目录启动 `dsh --profile <name>`。Runtime Retry 和进程意外退出不会消费后来加入的队列。监督器必须同时收到对应启动器经过认证的启动确认并观察到端口监听，才确认选择；失败子进程先被终止，再恢复选择。下次应用启动会拒绝持久化的未完成试启动。成功候选成为活动组合，其前任保留为元数据；后续崩溃不会自动降级。

单实例宿主串行处理选择操作。记录缺失时选择 `web`；记录损坏、版本未知、超限或为链接时阻止启动，而不重置记录。同目录原子替换和文件同步避免发布部分 JSON，但不承诺目录 fsync 级断电持久性，也不协调独立原生宿主。恢复写入失败时阻止下次启动，直到持久化成功。取消和恢复都不删除 Profile 或会话文件。

Cordis 准备服务读取原生前任，并直接在原主目录内创建候选。这样无需搬迁步骤即可保留复制后的依赖链接。准备回执和可选历史先提交，再发出原生请求。请求开始后，回复不确定会保留所有候选产物；删除它们可能破坏原生宿主已经提交的队列。原生提供方验证有大小上限的选择回复，并通过已有桌面服务定义提供排队、取消操作。两个组件都不重启活动工作。

## 考虑过的替代方案

**用单独的 Harness 主目录启用。** 不采用，因为运行中的桌面端必须保留已有会话、设置和凭据提供方。私有组合检查目录仍只用于验证。

**每次运行时重试都消费队列。** 不采用，因为恢复操作不等于授权替换所选插件组合。完整重启应用提供明确的启用时机，不增加自动中断任务的行为。

**后续任何崩溃都恢复前一个 Profile。** 不采用，因为成功启用的插件可能已经更改持久化数据。自动选择恢复仅限未提交的试启动，不撤销插件副作用。

## 后果

[原生打包测试](../../../../apps/desktop/src-tauri/src/runtime_profile_tests.rs)通过监督器启动真实 Node/CLI 产物，验证 Runtime Retry 不提前启用，确认 Harness 主目录不变，并实际执行故意失败的候选后恢复前任。原生单元测试覆盖中断的试启动、过期前任、取消、并发排队、损坏记录和持久化失败。[桌面工作流](../../../../.github/workflows/desktop.yml)负责在两个发布平台上执行；本地 macOS 证据不代表 Windows 行为已验证。

原生所有者选择 Cordis 准备好的 Profile；它不安装软件包，也不验证插件持续健康。打包测试通过 Cordis 服务、TypeScript 桥接提供方和 Rust 请求处理器排队真实审核 Bundle，再重启监督器。浏览器市场集成仍属于[市场提案](../../proposed/architecture/2026-09-06-desktop-plugin-marketplace.zh.md)中的工作。[桌面载体](2026-08-20-tauri-desktop-carrier.zh.md)和[组合准备](2026-09-07-candidate-profile-composition.zh.md)分别保留独立的生命周期及复制策略依据。无需修改 agent loop 或已发布的会话格式。
