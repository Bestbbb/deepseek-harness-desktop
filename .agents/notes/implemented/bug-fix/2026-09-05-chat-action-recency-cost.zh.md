# Agent Note: 限制长会话中操作行新近度的计算开销

Status: implemented

[English](2026-09-05-chat-action-recency-cost.md) | 中文

## 问题

[轮次操作附属元素](../feature/2026-08-03-web-turn-run-time.zh.md)使用的后继兄弟 `:has()` 规则，在数百条用户行保持挂载时产生高昂的样式失效开销。即使消息内容不变，输入框聚焦和消息插入也可能为许多行重复判断相同的兄弟关系。

## 决策

ChatView 在 order 改变时统一计算最新的用户或 steering key。记忆化的 seat 接收布尔值并发布 `data-actions-reveal`；CSS 只负责透明度、悬停和聚焦。这取代后继兄弟 CSS 机制，不改变轮次计时和新近度交互决策。行不会为反向扫描历史而订阅聚合状态。稳定节点的流式更新不会重新计算新近度。

改动保留全部已加载行、原生查找、选择和历史前插。组件测试覆盖初始新近度、追加 steering 和历史前插；样式测试拒绝重新引入 `:has()`。现有 500 轮浏览器基准保留相同历史、工具行和八轮续聊。计时是观测值而非 CI 阈值，也不构成原生 WebView 性能证据。

## 考虑过的替代方案

- **每行反向扫描：** 为每个已挂载消息重复订阅和搜索工作。
- **虚拟化或布局隔离：** 可能改善更长的会话，但需要单独验收选择、查找、代码吸顶标题、宽度和滚动锚点；移除此选择器开销不需要这些改动。
- **减少基准消息：** 改变工作量，而非优化渲染路径。

## 后果

追加消息时，只有先前和新的最新用户 seat 改变新近度。行顺序继续由一个所有者提供，消息和持久化 Session 格式不变。展开的大历史仍保留其 DOM；此改动不保证内存有界，也不消除全部样式与布局工作。
